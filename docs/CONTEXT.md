เอกสารนี้ให้ agent (หรือคนใหม่) อ่านจบแล้วทำงานต่อได้โดยไม่ต้องถามว่า "โปรเจกต์นี้คืออะไร ทำมาถึงไหน ห้ามทำอะไร"
อ่านตามลำดับ: §0 ก่อนแตะอะไรก็ตาม → §1–2 เพื่อเข้าใจว่าทำเพื่อใคร → §3–6 เพื่อรู้โครงสร้าง → §8 ก่อนแก้โค้ด → §10 เพื่อเลือกงานต่อ

สถานะ ณ วันที่ 13 พฤศจิกายน 2026: ประวัติ `main` ถูกเขียนใหม่เพื่อลบบรรทัด Co-Authored-By (hash เปลี่ยนทั้งหมด), working tree สะอาด, repo `namosarawut/stem-studio` ยังเป็น **private**

ไฟล์ที่เกี่ยวข้อง: [CLAUDE.md](../CLAUDE.md) (สรุปสั้นที่ Claude Code โหลดอัตโนมัติ), [ROADMAP.md](ROADMAP.md) (งานที่ยังไม่ทำ), [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md), [tools/promo/README.md](../tools/promo/README.md)

## 0. กฎเหล็ก (อ่านก่อนทำอะไร)

1. **`data/` คือเพลงจริงของผู้ใช้** (ประมาณ 33 เพลง, 31 GB, มี cue/เมโทรนอมที่แก้มือ และเพลย์ลิสต์) ห้ามลบ แก้ ย้าย หรือ "ล้างของที่ไม่รู้จัก" โดยไม่ได้รับอนุญาตชัดเจนจากผู้ใช้ เคยพลาดลบงานของผู้ใช้มาแล้วครั้งหนึ่ง
2. **ทดสอบบนข้อมูลสำเนาเสมอ** บนพอร์ต 8766 (วิธีใน §9) เซิร์ฟเวอร์จริงอยู่พอร์ต 8765 และผู้ใช้อาจเปิดใช้งานอยู่
3. **รีสตาร์ตเซิร์ฟเวอร์จริงเฉพาะตอนที่ `/api/jobs` ไม่มีงาน `queued` หรือ `running`** ไม่งั้นงานแยกเสียงที่กำลังทำจะถูกตัดและกลายเป็น error (`restore_jobs` ทำเครื่องหมายว่า "ถูกขัดจังหวะ")
4. **ห้าม commit/push จนกว่าผู้ใช้สั่ง** ห้ามเอา `data/`, `models/`, `.venv/`, `.claude/` เข้า git (เคยเผลอ commit เสียง 14 GB แล้วต้องล้างประวัติ) ก่อน commit ดู `git status` ทุกครั้ง และเพิ่มไฟล์ทีละชื่อ ไม่ใช้ `git add -A` **ข้อความ commit ห้ามมีบรรทัดอ้างถึง AI** (`Co-Authored-By: Claude …`, "Generated with Claude Code") ผู้ใช้สั่งชัด และเคยต้องเขียนประวัติใหม่เพื่อลบออก
5. **ตอบผู้ใช้เป็นภาษาไทย** ภาษาพูดธรรมชาติ ไม่เป็นทางการ ไม่ใช้สำนวนที่ฟังเหมือน AI เขียน (ผู้ใช้ขอแก้เรื่องนี้ซ้ำหลายรอบ ทั้งข้อความ UI สไลด์ โพสต์ และบทพากย์) ข้อความ UI ใหม่ก็ใช้แนวเดียวกัน
6. **ก่อนแก้ cue/เมโทรนอม/เพลย์ลิสต์ที่ผู้ใช้วางไว้เอง ให้ถามก่อน** งานของ Prism คือแก้ละเอียดด้วยมือ การเขียนทับถือเป็นความเสียหาย
7. **ไม่ใส่ข้อมูลส่วนตัว** (อีเมล ชื่อจริง) ลงโค้ด เอกสาร หรือ commit ลิขสิทธิ์ใน LICENSE ใช้ชื่อ GitHub `namosarawut`
8. **อย่าอ้างว่าเสร็จถ้ายังไม่ได้ลองจริง** โปรเจกต์นี้ไม่มี test suite อัตโนมัติ ต้องรันตรวจเอง (§9) และรายงานตามจริงว่าตรวจอะไรแล้วและอะไรยัง

## 1. Prism คืออะไร

เว็บแอปที่รันบนเครื่องของผู้ใช้เอง (Mac หรือ Windows, ไม่อัปโหลดเสียงขึ้นเน็ต; ถ้าผู้ใช้เชื่อม Claude ผ่าน MCP เอง Claude จะเห็นแค่ชื่อเพลง ท่อน cue และตัวเลขจังหวะ ดู §7) สำหรับนักดนตรีที่ต้อง **เตรียม data ให้วงเล่นสด / เป็น sound MD**:

- แยกเพลงเป็น stem ด้วย AI (Demucs; แยกร้องนำ/คอรัสด้วย MelBand Roformer)
- วิเคราะห์เพลง: BPM (รองรับเพลงที่ความเร็วเปลี่ยนกลางเพลง), คีย์, คอร์ด, ท่อนเพลง, loop
- แทร็กคลิก (เมโทรนอม) ที่ตามเพลงและแก้ละเอียดได้
- แทร็ก cue: เสียงพูดบอกท่อน (135 วลี) และนับเข้า 7 แบบ ลงตรงบีต
- ห้องนับก่อนเพลง (lead-in): UI ให้เลือก 1, 2, 3, 4 หรือ 8 ห้อง (API รับ 0–16 ตาม `MAX_LEAD_BARS`) ในสื่อโปรโมตเขียนว่า "1–8 ห้อง"
- ตัดช่วงเสียงไปเป็นแทร็กใหม่ (เช่น ดึงคอรัสท่อนฮุก) แบบย้อนกลับได้
- กำหนดต่อแทร็กว่าออกลำโพงซ้าย/ขวา/กลาง (ส่งคลิกเข้า in-ear ข้างหนึ่ง ดนตรีอีกข้าง)
- export ทุกแทร็กยาวเท่ากัน วางที่ 0 ใน DAW แล้วตรงกัน
- **เพลย์ลิสต์ (setlist player)** เล่นเพลงต่อกันแบบไม่มีช่องว่าง ตั้งจุดเริ่ม/จบรายเพลง นำเข้าไฟล์จากเครื่องหรือดึงจากโปรเจกต์ที่ทำไว้

ชื่อ: เดิมคือ "Stem Studio" เปลี่ยนเป็น **Prism** (ผู้ใช้เลือกเอง) โฟลเดอร์/repo/env var/localStorage key ยังใช้ชื่อเดิม **อย่าเปลี่ยน** (§8)

## 2. ผู้ใช้และบริบทการใช้งาน

- เจ้าของโปรเจกต์คือนักดนตรี/คนทำ data ชาวไทย ใช้ MacBook Pro M3 Pro 36 GB (พัฒนาและทดสอบ) ผู้ใช้ปลายทางคือเพื่อนร่วมวงการ ซึ่งอาจใช้ M1 8 GB
- เป้าหมายปัจจุบัน: **แจกฟรี เปิดโค้ดให้ต่อยอด (MIT)** แล้วโพสต์แนะนำในกลุ่มนักดนตรี
- ตัวอย่างเพลงที่ใช้ทดสอบหลักคือ "Circle" (เพลงที่ความเร็วเปลี่ยน) ภาพโปรโมตยังมีชื่อเพลงนี้ ถ้าเผยแพร่วงกว้างควรทำใหม่ด้วยเพลงที่มีสิทธิ์
- ผู้ใช้ไม่ใช่โปรแกรมเมอร์เต็มตัว ชอบให้ลงมือทำให้เลย แล้วรายงานสั้นๆ ว่าอะไรเปลี่ยน ถามเมื่อมีทางเลือกที่ผลต่างกันจริงเท่านั้น

## 3. สถาปัตยกรรม

```
Browser (vanilla JS, ไม่มี build)  ──HTTP──▶  FastAPI (app/main.py, 127.0.0.1:8765)
  static/app.js, playlist.js                     ├─ worker thread: คิวแยกเสียง (ทีละงาน)
  Web Audio API เล่น/ผสมเสียง                    ├─ analyzer / tempo / project / cues / playlists
                                                 └─ ffmpeg (imageio-ffmpeg), `say` (macOS)
ดิสก์: data/{jobs,library,playlists}, models/
```

- เซิร์ฟเวอร์ผูกเฉพาะ localhost และ middleware `local_only` ตรวจทั้ง `Host` และ `Origin` (กัน DNS rebinding / เว็บอื่นยิงมาที่เครื่องผู้ใช้) **อย่าเอาออก**
- งานแยกเสียงเข้าคิว `work_queue` ทำทีละงานใน thread `stem-worker` สถานะอยู่ใน dict `jobs` + `meta.json`
- อุปกรณ์: `separator.pick_device()` เลือก MPS (Apple GPU) ถ้ามี, ตั้ง `PYTORCH_ENABLE_MPS_FALLBACK=1`
- ตัวแก้ไข (`edits.json`) แยกจากไฟล์ต้นฉบับ: **stem ที่แยกแล้วใน `stems/` ไม่ถูกแก้เลย** ทุกการตัด/ห้องนับเรนเดอร์เป็นไฟล์ใหม่ใน `edited/` และ `padded/` แล้วย้อนได้

## 5. ข้อมูลบนดิสก์

```
data/jobs/<id 12 hex>/
  meta.json            สถานะ job: id, title, source, model, status, stage, progress, stems[], bpm, key, resources,
                       trim? {start, end|null} (ช่วงของไฟล์ที่ใช้แยก วินาทีของไฟล์ต้นฉบับ)
  source.<ext>         ไฟล์ต้นฉบับ
  stems/*.wav          stem ที่แยกแล้ว + click.wav + cues.wav (guide)  ← stem ห้ามแก้
  analysis.json        version, duration, tempo{bpm,stability,beats,downbeats,varying,map,range,...},
                       meter, key, chords, loops, sections, stems[], loudness, insights
  edits.json           การแก้มือ (ดูล่าง)
  edited/              ผลการตัดช่วง (เรนเดอร์จาก ops)
  warped/              แทร็กเพลงที่ล็อกความเร็วแล้ว (หลังตัดช่วง ก่อนเติม lead-in) + peaks.json
  padded/              stem ที่เติมความเงียบหน้าเพลงตาม lead-in
  cues_render.json     peaks และตำแหน่งบีตที่นับของแทร็ก cue
  tempo.mid            tempo map (สร้างใหม่ทุกครั้งที่ดาวน์โหลด)
  playback/<key>.wav|json   มิกซ์สำหรับเพลย์ลิสต์ (เก็บ 6 อันล่าสุด)
  stems.zip            cache ของ export (ถูกลบทุกครั้งที่เนื้อหา export เปลี่ยน)
data/library/<id>/     ไฟล์นำเข้า: audio.wav + meta.json (มี peaks) (สร้างตอนนำเข้าครั้งแรก)
data/playlists/<id>.json
  { name, auto_advance, gap, items: [ { id, kind: "file"|"project", ref, title,
      start, end|null, stop_after, fade_in, fade_out, mix?: { muted:[...], pan:{stem:"L"|"R"} } } ] }
models/                น้ำหนักโมเดล (TORCH_HOME) + models/cues/ (cache เสียง say) + models/separator/
```

`edits.json`:
```

  "tracks": [{id: "custom_xxxxxxxx", name, color, root}                                  // แทร็กที่ตัดมา
            | {id: "added_xxxxxxxx", name, color, kind: "file", offset, length, root: null}], // เสียงจากไฟล์
  "ops":    [{source, target, start, end}],           // ลำดับการตัด (เรนเดอร์ใหม่จากต้นฉบับ)
  "colors_used": n,
  "lead_in": null | {bars, seconds},
  "warp":   null | {bpm, src[], dst[], beats[], downbeats[], meter, range},  // ล็อกความเร็ว (time map เวลาเพลง→เวลาที่ล็อก)
  "cues":   [{kind: "phrase"|"count", time, text?/style?, voice, auto?}] }  // เวลาเพลง
```

## 6. API (ทั้งหมดอยู่ใน `app/main.py`)

| กลุ่ม | Endpoint |
|---|---|
| ระบบ | `GET /api/system`, `GET /api/version` (เปลี่ยนเมื่อรีสตาร์ตหรือไฟล์ใน static/ เปลี่ยน) |
| ถังขยะ | `GET /api/trash`, `POST /api/trash/{entry}/restore`, `DELETE /api/trash/{entry}` (ลบถาวร), `DELETE /api/trash` (ล้างทั้งหมด) |
| งาน | `GET/POST /api/jobs` (POST รับ `trim_start`, `trim_end` ได้), `GET/DELETE /api/jobs/{id}`, `GET /api/jobs/{id}/analysis` |
| เมโทรนอม | `PUT/DELETE /api/jobs/{id}/click` |
| ห้องนับ | `PUT /api/jobs/{id}/lead-in` |
| MCP / Claude | `GET /api/jobs/{id}/click/inspect?start&end&bpm` (ภาพรวม + บีตเทียบกลองในช่วง อ่านอย่างเดียว), `GET /api/jobs/{id}/changes?since=` (ใครแก้เพลงล่าสุด จาก header `X-Prism-Client`), `GET /api/mcp-setup` (ข้อความตั้งค่าพร้อม path ของเครื่องนี้) |
| ซ่อมเมโทรนอม | `POST /api/jobs/{id}/click/repair` `{beats, downbeats, meter, bpm?}` (เวลา timeline) คืนกริดที่ซ่อมแล้ว ไม่บันทึก |
| ล็อกความเร็ว | `PUT /api/jobs/{id}/tempo-lock` `{bpm: number|null, position?}` (null = ปลดล็อก) |
| cue | `GET /api/cues/library`, `GET /api/cues/preview`, `PUT /api/jobs/{id}/cues` |
| ตัดช่วง/แทร็ก | `POST /api/jobs/{id}/cuts`, `DELETE .../cuts/last`, `PATCH/DELETE .../tracks/{tid}` (PATCH รับ `name` และ/หรือ `start` สำหรับย้ายเสียงที่เพิ่มจากไฟล์) |
| เสียงจากไฟล์ | `POST /api/jobs/{id}/tracks` (multipart: `file`, `name`, `start` เวลา timeline) |
| เสียง/ส่งออก | `GET /api/jobs/{id}/stems/{stem}.wav`, `GET .../tempo.mid`, `GET .../download.zip` (มี `tempo.mid` ด้วย) |
| ไลบรารีนำเข้า | `GET/POST /api/library`, `GET/DELETE /api/library/{id}`, `GET .../audio.wav` |
| เล่นเพลย์ลิสต์ | `POST /api/jobs/{id}/playback`, `GET .../playback/{key}.wav` |
| เพลย์ลิสต์ | `GET/POST /api/playlists`, `GET/PUT/DELETE /api/playlists/{id}` |

ทุกการเขียนที่แก้ edits ทำใต้ `edit_lock` เสมอ และจบด้วยการลบ `stems.zip`

## 7. หลักการทำงานของฟีเจอร์ที่ซับซ้อน

**โมเดลแยกเสียง** (`separator.MODELS`): หน้าเลือกโมเดลโชว์ `MAIN_MODELS = ["htdemucs_6s", "htdemucs"]` (6 แทร็ก และมาตรฐาน) ส่วน `htdemucs_ft` (คุณภาพสูงสุด) และ `htdemucs_lead` (ร้องนำ+คอรัส) ซ่อนไว้ให้ผู้ใช้กดเปิดเอง ผู้ใช้สั่งชัดว่าให้ซ่อน

**วิเคราะห์จังหวะ** (ผ่านการจูนกับเพลงจริงหลายเพลงแล้ว ระวังก่อนแก้):
- ใช้ hop ที่หารความยาวบีตลงตัว (librosa ปัดเฟรมต่อบีต)
- เส้นโค้งความเร็ว (tempo curve) ถูกรับเมื่อตรงกับ hit ดีกว่า ≥ 1.5 เท่า (`CURVE_MIN_GAIN`)
- บีตถูก snap เข้าหา attack จริง (`SNAP_SECONDS = 0.035`)
- `tempo.py` แบ่งช่วงความเร็วด้วย penalty `SEGMENT_PENALTY` ที่จูนกับเพลงคงที่และเพลงที่เปลี่ยนความเร็ว
- เวอร์ชันวิเคราะห์ต่ำกว่า `ANALYSIS_VERSION` จะรันซ้ำอัตโนมัติจาก stem เดิมตอนเปิดเพลง (`upgrade_analysis`) **โดยเก็บการแก้มือไว้**; ถ้าปรับอัลกอริทึมจนผลต่าง ให้เพิ่มเลขนี้

**ตัดช่วงก่อนแยก** (`chooseRange` ใน app.js, `clean_trim`/`apply_trim` ใน main.py): ตอนวางไฟล์ เบราว์เซอร์ถอดรหัสไฟล์เพื่อโชว์คลื่นเสียง (ไฟล์เกิน 400 MB หรือเบราว์เซอร์อ่านไม่ได้ ข้ามไปแยกทั้งเพลง) ผู้ใช้ลากเส้นเริ่ม/จบ ส่งไปแค่ตัวเลขสองค่า เซิร์ฟเวอร์เก็บไฟล์ต้นฉบับทั้งก้อน แล้วตัดเสียงหลังถอดรหัสใน `process()` ดังนั้น stem, analysis และทุกอย่างหลังจากนั้นเริ่มที่ 0 = จุดเริ่มที่เลือก ช่วงต้องยาว ≥ 1 วินาที

**ฐานเวลา**: `edits.json` เก็บ **เวลาเพลง** (ของ stem ต้นฉบับ); API และ UI ใช้ **เวลา timeline = warp(เวลาเพลง) + lead-in** แปลงด้วย `project.to_timeline` / `project.to_song` เท่านั้น (warp เป็น identity เมื่อไม่ได้ล็อก) ที่ขอบ API (ดู `save_cues`, `create_cut`, `render_cues`, `write_tempo_midi`) นี่คือจุดที่บั๊กเกิดง่ายที่สุด ห้ามเขียน `+ lead` / `- lead` เองอีก

**ล็อกความเร็ว** (`warp.py`, `project.lock_tempo`, `PUT /tempo-lock`, ช่อง "ล็อกความเร็ว" ข้างช่วงนับ): เพลงที่อัดโดยไม่มีคลิกจะไหล (เช่น "ยื้อ" 164–174 BPM) ล็อกแล้วเสียงทุกแทร็กถูกยืด/หดทีละบีตให้ทุกบีตยาว 60/bpm
- time map: บีตแรกอยู่ที่เดิม (ก่อนหน้านั้นและ lead-in เป็น 1:1), บีตที่ n ของเพลงไปอยู่บีตที่ n ของกริดคงที่, หลังบีตสุดท้าย 1:1 บีตที่ห่างจากเส้นของเพื่อนบ้านเกิน 30 ms (`KINK_SECONDS`) ไม่ถูกใช้เป็นจุดยึด
- ถ้าช่วงไหนต้องยืดเกิน 15% (`MAX_STRETCH`) จะไม่ล็อก แต่บอกเวลาที่ต้องแก้ (มักเป็นบีตเกิน/ขาดในเมโทรนอม) ถ้า BPM ที่ขอห่างจากค่าเฉลี่ยเกิน 20–25% ก็ไม่ล็อก (บอกเรื่อง ×2/÷2)
- ยืดด้วย WSOLA ที่เขียนเอง (ไม่มี dependency เพิ่ม): เลือกจุดต่อเฟรมครั้งเดียวจากเสียงรวมทุกแทร็ก แล้วใช้จุดเดียวกันกับทุกแทร็ก แทร็กจึงยังรวมกันได้เท่าเพลงเดิม ระดับเสียงไม่เปลี่ยน ทดสอบกับ "ยื้อ" 6 แทร็ก 5.5 นาทีใช้ 7.5 วินาที กลองหลังยืดห่างคลิก median 9 ms เท่ากับก่อนยืด
- ลำดับเรนเดอร์: `stems/` → ตัดช่วง `edited/` → ล็อก `warped/` → lead-in `padded/` (`serve_path` เลือกตัวสุดท้ายที่มี) การตัดช่วงขณะล็อกจะยืดใหม่ทั้งชุด
- ขณะล็อก แก้เมโทรนอมไม่ได้ (409) กริดคือค่าคงที่จาก snapshot ใน `edits.warp`; ช่วงนับคำนวณใหม่ตามความเร็วที่ล็อก; cue/ท่อน/คอร์ดย้ายตาม time map; MIDI เขียน tempo ค่าเดียว
- ปลดล็อกแล้วไฟล์ที่เสิร์ฟกลับมาเหมือนก่อนล็อกทุกไบต์ (ทดสอบแล้ว)

**ถังขยะ** (`trash.py`): ลบเพลง ไฟล์นำเข้า หรือเพลย์ลิสต์ = ย้ายไป `data/trash/<kind>-<id>-<สุ่ม>/item` + `trash.json` (ชื่อ, เวลาลบ, ขนาด, งานแก้มือของเพลง) เก็บ 7 วันแล้วลบจริงตอนเปิดเซิร์ฟเวอร์หรือเปิดรายการ กู้คืนไม่ได้ถ้ามีของ id เดียวกันอยู่แล้ว หน้าแรกมีส่วน "ถังขยะ" (กู้คืน / ลบถาวร / ล้างทั้งหมด) ปุ่มลบในหน้าแรกเตือนว่ามีงานแก้มืออะไร (`work` ใน `/api/jobs`) เหตุผล: ผู้ใช้เคยลบเพลงที่แก้เมโทรนอมและล็อกไว้แล้วกู้ไม่ได้

**แถบ "มีเวอร์ชันใหม่"**: หน้าเว็บเช็ก `/api/version` ทุก 20 วินาทีและตอนกลับมาที่แท็บ ถ้าเปลี่ยน (รีสตาร์ตเซิร์ฟเวอร์ หรือแก้ไฟล์ใน static/) ขึ้นแถบให้กดโหลดใหม่ เหตุผล: ผู้ใช้เปิดหน้าเก่าค้างแล้วไม่เห็นปุ่มใหม่หลายครั้ง

**ทำคลิกให้นิ่ง** (ปุ่มเดียวข้างช่องล็อกความเร็ว): เลือกความเร็ว (เสนอค่าเฉลี่ยกับ ×2 หรือ ÷2 เลือกตัวที่อยู่ 90–180 ให้) → `click/repair` (ถ้า BPM ห่างค่าเฉลี่ยเกิน 20–25% จะ ×2/÷2 กริดก่อน, ถ้ากริดไม่ตามกลองจะสร้างใหม่จากเมโทรนอมอัตโนมัติ) → ใส่ผลในตัวแก้ (ย้อนกลับได้) + บันทึก → `tempo-lock` ถ้าล็อกไม่ผ่านจะคืนเมโทรนอมเดิมให้ และเสนอให้ Claude ช่วย ผลลัพธ์บอก "จุดที่ควรฟัง" (`project.listen_spots`: ช่วงที่ยืดเกิน 10% และห้องที่จังหวะไม่ครบ) กดแล้วกระโดดไปฟัง; ตอนล็อกอยู่ ปุ่มเปลี่ยนเป็น "จุดที่ควรฟัง (n)" ปุ่ม "ตั้งเป็นจังหวะคงที่ (ทั้งเพลง)" เตือนก่อนถ้าเพลงไหลเกิน 3%

**เพิ่มเสียงจากไฟล์** (ปุ่ม "+ เพิ่มเสียงจากไฟล์" ในหน้าเพลง หรือลากไฟล์มาวาง): sample / เสียงเอฟเฟกต์ / ท่อนที่อัดเพิ่ม เป็นแทร็กใหม่ใน `edits.tracks` (`kind: "file"`)
- ถอดรหัสด้วย ffmpeg (`decode_audio`) เก็บ `added/<id>.src.wav` แล้ววางบนเพลงเป็น `added/<id>.wav` ยาวเท่าเพลง (`render_added`) ส่วนที่เกินท้ายเพลงถูกตัด
- เก็บตำแหน่งเป็นเวลาเพลง (`offset`, ติดลบได้ = อยู่ในช่วงนับ) จึงอยู่กับจังหวะเดิมของเพลงเมื่อเปลี่ยนช่วงนับ; **ไม่ถูกยืดตอนล็อกความเร็ว** (`build_warped` วางที่ warp(offset) ความยาวเดิม) เพราะเสียงที่เอามาใส่มักทำมาที่ความเร็วที่ล็อกแล้ว
- ตัดช่วงจาก/เข้าแทร็กนี้ไม่ได้ ย้ายได้ด้วยปุ่ม ⇥ (เริ่มที่ตำแหน่งเล่น), ลบด้วย × (ลบไฟล์ใน added/ ด้วย), ส่งออก ZIP/เพลย์ลิสต์ได้เหมือน stem อื่น
- waveform ของเสียงที่อยู่ในช่วงนับมาจาก `padded/peaks.json`

**โหมดโชว์** (`show.js`, ปุ่ม "โหมดโชว์" บนแถบเพลย์ลิสต์): หน้าจอเต็มที่ใช้ `plPlayer` ตัวเดิม (ไม่เล่นเสียงเอง) `plRenderNow`/`plRenderClock` เรียก `plShowRender()` ทุกครั้ง
- แสดง: ชื่อเพลงใหญ่, สถานะ, ท่อนที่กำลังเล่น + ท่อนถัดไปอีกกี่วินาที (จาก sections ของโปรเจกต์), เวลาที่ผ่าน/ที่เหลือ, เพลงถัดไปและเล่นต่อทันทีหรือหยุดรอ, นาฬิกา
- รายการเพลงด้านขวา (`showRenderList`, ซ่อน/แสดงด้วยปุ่ม "รายการเพลง", จอแคบเป็นแผงลอย): ↑ ↓ ย้ายลำดับ (บันทึกและ `replan` เพลงถัดไป), แตะเพลง = ตั้งเป็นเพลงถัดไปตอนหยุดอยู่ / แตะสองครั้งภายใน 3 วินาทีเพื่อเปลี่ยนทันทีตอนกำลังเล่น, "+ เพิ่มเพลง" เปิด picker ของหน้าเพลย์ลิสต์ให้เพลย์ลิสต์ที่กำลังเล่น (`plOpenPicker(list)`)
- picker มีแท็บ "จากเพลย์ลิสต์อื่น" (`plRenderPickerLists`) คัดลอกเพลงพร้อมจุดเริ่ม/จบ/มิกซ์ (id ใหม่ ต้นทางไม่เปลี่ยน) ทีละเพลงหรือทั้งเพลย์ลิสต์; ใช้ได้ทั้งหน้าเพลย์ลิสต์และโหมดโชว์ `plSave(changedId, replan, list)` บันทึกเพลย์ลิสต์ที่ระบุ (timer แยกต่อเพลย์ลิสต์)
- คีย์: Space/Enter = เล่น-หยุด, → ↓ PageDown = เพลงถัดไป, ← ↑ PageUp = ก่อนหน้า/ต้นเพลง (แป้นเหยียบส่วนใหญ่ส่งปุ่มเหล่านี้), Esc = ออก รับใน capture phase แล้ว stopPropagation
- MIDI (Chrome/Edge): "ตั้งแป้น MIDI" → ตั้งปุ่ม → เหยียบ รับ note-on (vel>0), CC (ค่า ≥64), program change เก็บใน localStorage `prism-show-midi`; ขอสิทธิ์ MIDI ตอนเปิดแผงหรือเมื่อมีค่าที่ตั้งไว้แล้วเท่านั้น
- ล็อกจอ: แตะ/คลิกในหน้าจอถูกกันทั้ง pointerdown และ click (capture) ยกเว้นปุ่มล็อก/ออกที่ต้องกดค้าง 1.2 วินาที คีย์และ MIDI ยังใช้ได้
- Wake Lock (ขอใหม่เมื่อกลับมาที่แท็บ), เต็มจอ, `beforeunload` เตือนเมื่อกำลังเล่นหรืออยู่ในโหมดโชว์, `route()` ไม่ยอมออกจากหน้าเพลย์ลิสต์ระหว่างโหมดโชว์
- ไอคอนเล่น/หยุดต้องใช้ `toggleAttribute("hidden")` เพราะ SVG ไม่มี `.hidden` (เคยเป็นบั๊กในแถบเพลย์ลิสต์ ไอคอนไม่เปลี่ยน)

**ใช้กับ Claude ผ่าน MCP** (`mcp_server.py`, ปุ่ม "เชื่อมกับ Claude" ที่หน้าแรก) แทนปุ่ม "ให้ Claude ช่วยดู" เดิม (ลบแล้ว พร้อม `assistant.py`, `bench_mcp.py` และ dependency `anthropic`)
- Claude Desktop / Claude Code รัน `<venv python> -m app.mcp_server` เองผ่าน stdio (`PYTHONPATH` = โฟลเดอร์ repo, `STEM_STUDIO_PORT`) หน้าต่างตั้งค่ามี JSON และคำสั่ง `claude mcp add` พร้อม path จริง ต้องเปิด Prism ค้างไว้
- เครื่องมือ 18 ตัว: `list_songs`, `choose_song` (ถ้า client รองรับ elicitation จะเด้งรายการให้ผู้ใช้คลิกเลือกเพลง ไม่งั้นคืนรายชื่อให้ Claude ถาม), `song_overview`, `check_metronome`, `inspect_beats`, `repair_metronome`, `replace_beats`, `set_beat_one`, `shift_metronome`, `reset_metronome`, `lock_tempo`, `make_click_steady`, `get_cue_library`, `auto_cues` (พอร์ตจาก `autoCues` ในหน้าเว็บ), `add_cue`, `remove_cues`, `set_lead_in`, `undo` (เก็บสถานะก่อนแก้ในหน่วยความจำของ session สูงสุด 30 ขั้นต่อเพลง)
- ทุกการแก้เรียก API เดียวกับหน้าเว็บ (บันทึก render และล้าง ZIP เหมือนกด) เวลาเป็นเวลา timeline ทั้งหมด header `X-Prism-Client: claude`; หน้าเพลงที่เปิดอยู่ poll `/changes` ทุก 2.5 วิ แล้วขึ้นแถบ "Claude แก้เพลงนี้แล้ว" พร้อมปุ่มโหลดเพลงใหม่ (การแก้ของหน้าเองไม่ขึ้น เพราะมี `PAGE_ID`)
- สิ่งที่ Claude เห็นคือผลของเครื่องมือเท่านั้น: ชื่อเพลง ท่อน cue เวลาบีตและเสียงกลอง/เบส ไม่มีไฟล์เสียง **ถ้าเพิ่มข้อมูลที่เครื่องมือคืน ต้องแก้ข้อความในหน้าต่างเชื่อมและ README ด้วย**
- ทดสอบแล้ว: client จำลองผ่าน stdio กับสำเนา (เลือกเพลงด้วย elicitation, ลบบีตแล้วซ่อมกลับ, cue อัตโนมัติ/เพิ่มเอง/นับเข้า, ช่วงนับ, ล็อก, undo จนกลับเป็นเหมือนเดิม, client ไม่มี elicitation) และแถบแจ้งในหน้าเว็บ; ยังไม่ได้ลองกับ Claude Desktop จริง

**ซ่อมเมโทรนอมอัตโนมัติ** (`gridfix.py`, ปุ่ม "ซ่อมจุดที่เพี้ยน" ในแผงแก้เมโทรนอม): หาจุดเดียวกับที่การล็อกจะยืดเกิน 10% (จุดที่ห่างกันไม่เกิน 16 บีตรวมเป็นจุดเดียว) แล้วสร้างใหม่จากเสียงกลอง (onset ของ stem กลอง, cache ในหน่วยความจำ)
- ยึดหัวท้ายด้วยบีตที่ตรงหัวกลองติดกันสองบีต ลองช่วงใกล้ก่อนแล้วขยายออก 2 ครั้ง เลือกช่วงที่ไม่ต้องเปลี่ยนจำนวนบีตก่อน (มักเป็นบีตหนึ่งเร็วไปอีกบีตช้าไป)
- เปลี่ยนจำนวนบีตเฉพาะจุดที่หนัก (>15%) มีกลองยึดทั้งสองข้าง และความเร็วรอบข้างบอกจำนวนได้ชัด (ห่างจำนวนเต็มไม่เกิน 0.3) จุดที่ไม่มีกลองแค่จัดระยะใหม่
- เกลี่ยระยะเท่ากันแล้วขยับบีตลงหัวกลองที่ห่างไม่เกิน 40 ms; หัวห้องนับต่อจากหัวห้องก่อนจุด ห้องที่สั้น/ยาวผิดปกติจึงอยู่ก่อนหัวห้องเดิมถัดไป ไม่ยอมให้เกิดห้อง 1 จังหวะ; ไม่ใช้ผลถ้าบีตใหม่ลงหัวกลองน้อยกว่าเดิมชัดเจน
- ถ้าเมโทรนอมทั้งเส้นไม่ตามกลอง (`drift_share`: เกิน 20% ของเพลงที่ค่ากลางของ 16 บีตห่างกลองเกิน 35 ms เช่นผู้ใช้กด "ตั้งเป็นจังหวะคงที่" กับเพลงที่ไหล) จุดเฉพาะจะหาไม่เจอ endpoint จึงเริ่มใหม่จากเมโทรนอมอัตโนมัติใน analysis ปรับ ×2/÷2 ให้ใกล้ BPM ที่ใช้อยู่ (`scaled_grid`) แล้วค่อยซ่อม และตอบ `rebuilt` ให้หน้าเว็บบอกผู้ใช้
- หน้าเว็บเอาผลใส่ตัวแก้ไข (กดย้อนกลับได้) แล้วบันทึกตามปกติ ระหว่างล็อกใช้ไม่ได้ (409)
- ทดสอบกับ "ยื้อ": จากเมโทรนอมอัตโนมัติ ×2 กดซ่อมแล้วล็อก 168 ผ่าน ยืดสูงสุด −10.9%/+13.4% กลองห่างคลิก median 7.3 ms ดีกว่าที่ผมแก้มือ เพลงที่ความเร็วนิ่งไม่ถูกแตะ

**ทุกแทร็กยาวเท่ากัน** (`timeline_samples` = ความยาวเพลง + lead-in) เพื่อให้ export วางที่ 0 แล้วตรงกัน

**นับเข้า (count-in)**: วางเทียบกับบีตที่ใกล้ที่สุด (ในระยะ 0.4 × ช่วงบีต) จึงอยู่รอดเมื่อแก้ grid, เมโทรนอมเปลี่ยนแล้วต้อง re-render cue; สไตล์ `gap1/2/3` สร้างจาก `[คำ] + [None]*gap` ต่อเลข

**การเขียนไฟล์แบบ atomic ทุกที่** (`write_wav_atomic`, `project._swap_dir`, `playlists.write_json_atomic`, `save_edits`): เบราว์เซอร์อาจกำลังดาวน์โหลดไฟล์ตอนมันถูกสร้างใหม่

**MIDI tempo map** (`midi.tempo_map`, ปุ่ม "Tempo map" และใน ZIP): SMF type 1, PPQ 960 สร้างจาก `timeline_grid` (เวลาเดียวกับ WAV ที่ export) แทร็ก 1 มี tempo หนึ่งค่าต่อหนึ่งบีต (ปัดจากผลรวมสะสม คลาดไม่ถึง 1 µs) + time signature + marker ชื่อท่อน แทร็ก 2 มีโน้ตคลิกทุกบีต (ช่อง 10, ตัวเน้นโน้ต 76) ช่วงก่อนบีตแรกเติมจำนวนบีตที่ทำให้ห้องแรกของเพลงตรงห้องใน DAW โดยไม่เปลี่ยน time signature (GarageBand ใช้ time signature เดียวทั้งโปรเจกต์ และเอาค่าแรกในไฟล์) ความเร็วช่วงนั้นจึงอาจสูงมาก (สูงสุด 990 BPM ตามที่ GarageBand/Logic รับ) ถ้าเกินจึงใช้ห้องสั้นแทน ห้องที่ยาวไม่เท่า meter ได้ time signature ของตัวเอง (GarageBand ไม่สนค่านี้) ลองเปิดใน GarageBand 10.4 แล้ว: ได้ 4/4, tempo track ครบ, บีตแรกอยู่ห้อง 2

**ซ้าย/ขวา (routing)**: เลือก L หรือ R จะรวมแทร็กเป็นโมโนด้วย (L+R)/2 เพื่อให้เสียงกลางคงระดับ กฎเดียวกันทั้งฝั่งเบราว์เซอร์ (`makeRoute` ใน app.js) และฝั่ง server (`playlists.render_mix`) **ต้องแก้คู่กันเสมอ** ค่าที่ตั้งในหน้าเพลงเก็บใน localStorage ต่อเพลง

**เพลย์ลิสต์**: 
- เพลงจากโปรเจกต์ถูกเรนเดอร์เป็นมิกซ์ฝั่ง server (`POST /playback`) แล้ว cache ใน `playback/` (ใช้ `mix_key` เป็นชื่อ)
- `plPlayer` เล่นด้วย `source.start(when, offset, duration)` บนนาฬิกาของ AudioContext พร้อม gain envelope โหลดเพลงถัดไปล่วงหน้าเพื่อให้ต่อกันไม่สะดุด
- สลับมิกซ์ระหว่างเล่น: `play()` รับฟังก์ชันตำแหน่งที่ประเมินหลังเสียงใหม่โหลดเสร็จ (เคยเริ่มผิดตำแหน่งเพราะประเมินก่อน)
- ปุ่มลัด "cue+คลิกไปขวา ดนตรีไปซ้าย" มีทั้งในหน้าเพลงและในตัวแก้ไขเพลงของเพลย์ลิสต์

## 8. กับดักและข้อตกลงที่ห้ามพลาด

- **ชื่อเดิมต้องคงไว้หลังเปลี่ยนเป็น Prism:** `STEM_STUDIO_DATA`, `STEM_STUDIO_PORT`, localStorage `stem-studio:pan:<job>` และ `stem-studio-cue-voice`, ชื่อโฟลเดอร์/repo เปลี่ยนแล้วผู้ใช้เก่าเสียค่าที่ตั้งไว้
- **ชื่อไฟล์ export เป็นชื่อเครื่องดนตรีอย่างเดียว** (`drums.wav` ไม่มีชื่อเพลง) ชื่อซ้ำให้ต่อท้ายด้วย id ZIP ตั้งชื่อตามเพลง ผู้ใช้สั่งชัด
- **UI ใหม่ใช้ภาษาไทยพูด** แบบเดียวกับที่มีอยู่
- ฝั่ง front ไม่มี build: ใช้ `el()` และ `api()` ที่มีอยู่, router แบบ hash ใน `route()`, ชื่อ view ใน `show()`, listener ต่อ view ผูกกับ `AbortController` แล้วเคลียร์ใน `leaveView` ถ้าเพิ่ม view ใหม่ต้องทำตามนี้ ไม่งั้น listener รั่วข้ามหน้า
- `static/` ส่ง `Cache-Control: no-cache` แก้แล้วรีโหลดก็เห็น (ถ้ายังเห็นของเก่า ให้ hard reload) ส่วนโค้ดใน `app/` ต้องรีสตาร์ต
- เสียง cue ใช้ `say` ของ macOS เรียกด้วยชื่อเสียงจากรายการ `VOICE_CHOICES` เท่านั้น (ไม่ส่งข้อความจากผู้ใช้เป็นชื่อเสียง) cache ที่ `models/cues/` และมีตัวตัดความเงียบหน้าคำ
- ความยาวทั้งหมดในเพลย์ลิสต์เป็น "ประมาณ" จนกว่าจะเรนเดอร์มิกซ์ (เพราะยังไม่รู้ความยาว timeline ถ้าตั้งจุดจบไว้ท้ายเพลง) — ดู §10
- ขีดจำกัดในโค้ดที่มีไว้กันข้อมูลบวม: `MAX_TRACKS = 24`, `MAX_OPS = 500`, `MAX_BEATS = 20000`, `MAX_CUES = 500`, `MAX_ITEMS = 300`, `MAX_PLAYLISTS = 200`, อัปโหลดสูงสุด 1 GB ต่อไฟล์

## 12. ประวัติการตัดสินใจ (ทำไมถึงเป็นแบบนี้)

- **ไม่มีเฟรมเวิร์กฝั่งหน้าเว็บ** เพื่อให้เปิดโค้ดแล้วแก้ได้เลยไม่ต้อง build และให้ `start.command` ไฟล์เดียวพอ
- **แก้แบบไม่ทำลาย** (ops → เรนเดอร์ใหม่) หลังจากผู้ใช้ต้องการลองตัดแล้วย้อนได้ และกันไม่ให้ stem ต้นฉบับเสีย
- **สองฐานเวลา** เกิดจากฟีเจอร์ lead-in: ความเงียบก่อนเพลงต้องไม่ทำให้ cue/บีตที่แก้มือเลื่อน จึงเก็บเวลาเพลงไว้และบวก lead ตอนส่งออก
- **เพลย์ลิสต์เรนเดอร์มิกซ์ที่ server** เพื่อให้เบราว์เซอร์โหลดไฟล์เดียวต่อเพลงและต่อกันไม่สะดุด (ข้อเสียที่รู้: เอาต์พุตสเตอริโอเท่านั้น → P2; ความดังรายแทร็กเปลี่ยนแล้วต้องเรนเดอร์ใหม่ ~1 วินาที จึงมีผลตอนปล่อยแถบเลื่อน)
- **ตัวเลือก L/R รวมเป็นโมโนด้วย (L+R)/2** แทนการตัดช่องทิ้ง เพื่อให้เสียงกลาง (ร้อง กลอง) ไม่เบาลง
- **ไม่ถือว่า Prism แทน DAW สำหรับงานใหญ่** ตอบผู้ใช้ไว้แล้วว่าเหมาะเป็นเครื่องมือเตรียม data งานทุกขนาด ส่วนตัวเล่นเพลย์ลิสต์เหมาะงานเล็กถึงกลาง งานใหญ่ควร export ไปเล่นใน DAW (ดู ROADMAP §1) อย่าโฆษณาเกินจริง
- **ไลเซนส์ MIT สำหรับโค้ด** แต่ส่วนประกอบมีเงื่อนไขของตัวเอง (say, โมเดล karaoke, ffmpeg GPL, lameenc LGPL, Demucs ฝึกด้วย MUSDB) สรุปไว้ใน THIRD_PARTY_NOTICES.md และ README ผู้ใช้ถามเรื่องนี้เองและต้องการความโปร่งใส ห้ามเขียนในเอกสารว่า "ใช้เชิงพาณิชย์ได้ไม่มีข้อจำกัด"
