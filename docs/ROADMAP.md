# Prism — สิ่งที่ควรปรับปรุง

รวบรวมจากการคุยและทดสอบจริง (พฤศจิกายน 2026) เรียงตามความสำคัญ ภาพรวมสถาปัตยกรรมอยู่ใน [CLAUDE.md](../CLAUDE.md)

## 1. ให้ใช้กับงานใหญ่ได้

ตอนนี้ Prism เหมาะเป็น**เครื่องมือเตรียม data** สำหรับงานทุกขนาด แต่**ตัวเล่นเพลย์ลิสต์**เหมาะกับงานเล็กถึงกลางเท่านั้น สิ่งที่งานใหญ่ต้องการแต่ยังไม่มี:

| ลำดับ | งาน | รายละเอียดและแนวทาง |
|---|---|---|
| P1 | **Export สำหรับ DAW** | ~~ไฟล์ MIDI tempo map~~ ทำแล้ว (`app/midi.py`, ปุ่ม Tempo map และใน ZIP) เปิดใน GarageBand ได้ (ยังไม่ได้วัดว่าคลิกตรงถึงท้ายเพลงใน DAW); ที่เหลือ: เลือก 48 kHz และ 24-bit ได้ (ตอนนี้ 44.1 kHz และ `write_wav_atomic` เขียน 16-bit) |
| P2 | **เพลย์ลิสต์หลายช่อง** | เลือกการ์ดเสียง (`AudioContext.setSinkId`) และส่งแต่ละแทร็กออกช่องที่กำหนด (`destination.channelCount` ตาม `maxChannelCount` + `ChannelMergerNode` N ช่อง) ตอนนี้ server รวมเป็นสเตอริโอ (`playlists.render_mix`) ต้องเปลี่ยนเป็นโหลด stem แยก หรือเรนเดอร์ WAV หลายช่อง |
| P3 | **โหมดโชว์** | สั่งเพลงถัดไปด้วย footswitch หรือ Web MIDI (footswitch หลายรุ่นส่งเป็นปุ่ม PageDown/ลูกศร); ล็อกหน้าจอกันกดผิด; เตือนก่อนปิดแท็บ (`beforeunload`); Wake Lock กันเครื่องหลับ |
| P4 | Timecode | export แทร็ก LTC หรือส่ง MIDI clock/MTC ให้ไฟและวิดีโอเล่นตาม |
| P5 | ระบบสำรอง | เครื่องหลักกับเครื่องสำรองเล่นซิงก์กัน อาจเกินขอบเขตของโปรแกรมนี้ ให้ DAW ทำแทนได้ |

ข้อจำกัดอื่นที่ควรบอกผู้ใช้: stem จาก AI ยังมีเสียงเครื่องอื่นติดมาบ้าง ซึ่งได้ยินชัดกว่าบน PA ใหญ่ ถ้าหา multitrack ของจริงได้ควรใช้ของจริง

ทำแล้ว: **ล็อกความเร็วคงที่** (`app/warp.py`) ยืดเสียงให้ทุกบีตเท่ากัน สำหรับเพลงที่อัดโดยไม่มีคลิก ยังไม่ได้ฟังเทียบด้วยหูกับเพลงจริงหลายเพลง; มีปุ่ม "ซ่อมจุดที่เพี้ยน" (`app/gridfix.py`) ซ่อมเมโทรนอมจากกลองก่อนล็อกแล้ว; ต่อยอดได้: ปุ่มกระโดดไปจุดที่ต้องแก้เมโทรนอมตอนล็อกไม่ผ่าน, ซ่อมสำหรับเพลงที่ไม่มีกลอง, ตัวเลือกยืดคุณภาพสูง (Rubber Band) ถ้าเครื่องมี

## 2. ไลเซนส์ ก่อนแจกหรือขาย

| เรื่อง | ความเสี่ยง | ทางแก้ |
|---|---|---|
| เสียงไกด์ใช้ `say` ของ macOS | สูง: ไลเซนส์ macOS อนุญาตเสียงระบบเฉพาะใช้ส่วนตัวที่ไม่ใช่เชิงพาณิชย์ งานจ้างจึงติด | ให้ `cues.py` ใช้ชุดไฟล์เสียงที่อัดเอง (หรือให้ผู้ใช้นำเข้าเอง) แทน `say` โดยใช้ cache และระบบตัดเสียงเงียบหน้าคำที่มีอยู่แล้ว |
| โมเดล `mel_band_roformer_karaoke_aufr33_viperx` (โหมดร้องนำ+คอรัส) | ไม่พบไลเซนส์ในแพ็กเกจหรือไฟล์โมเดล | ขออนุญาตผู้ทำ หรือปิดโหมดนี้ในเวอร์ชันแจก/ขาย |
| ไฟล์ ffmpeg จาก imageio-ffmpeg | คอมไพล์แบบ `--enable-gpl` ถ้าแพ็กแอปรวมไฟล์นี้ไปแจก ต้องทำตาม GPL | ใช้ ffmpeg เวอร์ชัน LGPL ที่มีเฉพาะตัวถอดรหัสเสียง หรือให้ผู้ใช้ติดตั้งเอง |
| Demucs | โค้ดและโมเดลเป็น MIT แต่เทรนด้วย MUSDB-HQ ซึ่งให้ใช้เพื่องานวิจัย | ถามนักกฎหมายก่อนขาย |
| Repo | เพิ่ม `LICENSE` (MIT) และ `THIRD_PARTY_NOTICES.md` แล้ว แต่ repo ยังเป็น private | เปลี่ยนเป็น public เมื่อพร้อมแจก |
| lameenc (LGPL-3.0) | Demucs ดึงมาใช้ ถ้าแพ็กแอปรวมไปแจกต้องทำตาม LGPL | ดูใน `THIRD_PARTY_NOTICES.md` |

## 3. ติดตั้งและใช้งาน

- ต้องมี Python 3.10–3.12 ในเครื่อง ไม่อย่างนั้น `start.command` รันไม่ขึ้น ควรทำตัวติดตั้งแบบรวม Python ไปด้วย หรืออย่างน้อยบอกวิธีติดตั้งใน README
- ครั้งแรกต้องต่อเน็ตเพื่อโหลดโมเดลประมาณ 1.3 GB
- **เครื่อง RAM 8 GB (เช่น M1):** ข้อมูลจาก 34 งานบน M3 Pro 36 GB: RAM สูงสุด 2.4–5.3 GB และหน่วยความจำ GPU 1.45 GB ต่อเพลง น่าจะรันได้แต่อาจใช้ swap ควรทำโหมดประหยัด RAM (แบ่งเพลงเป็นช่วงสั้นลง และคืนหน่วยความจำระหว่างแต่ละขั้น)
- รองรับแค่ macOS (MPS และ `say`)

## 4. งานเล็กที่ค้างอยู่

- ความยาวรวมของเพลย์ลิสต์ขึ้นคำว่า "ประมาณ" จนกว่าจะเปิดหรือเล่นเพลงจากโปรเจกต์ที่ตั้งจบไว้ที่ท้ายเพลง เพราะความยาวรู้หลังเรนเดอร์มิกซ์ ทางแก้: ให้ server ส่งความยาว timeline มาโดยไม่ต้องเรนเดอร์
- เพลย์ลิสต์รับแค่การเปิด/ปิดแทร็ก ไม่รับระดับเสียงจาก fader (`render_mix` ไม่มี gain ต่อแทร็ก)
- ปุ่มฟังตัวอย่างของ cue แบบ "นับเว้น" อ่านตัวเลขติดกัน ไม่ได้เว้นจังหวะ
- ครั้งแรกที่เล่นเพลงจากโปรเจกต์ใช้เวลาเรนเดอร์มิกซ์ประมาณ 1 วินาที ครั้งต่อไปใช้ cache
- ออกจากหน้าเพลย์ลิสต์แล้วเพลงหยุด (ตั้งใจไว้ กันเสียงซ้อนกับหน้าเพลง)
- ค่าลำโพงซ้าย-ขวาในหน้าเพลงเก็บใน localStorage ของเบราว์เซอร์ ไม่ตามไปเครื่องอื่น
